# REVIEW routine — one due name per run (MODEL §8.2 under §8.7)

**Schedule:** Monday–Friday at 06:10 and 21:10 Europe/Prague; weekend sprint Friday 22:20 and 23:20, Saturday hourly at :20, Sunday 00:20–07:20 hourly at :20.
Weekdays 09:00–18:00 are routine-free and 02:00–06:00 is quiet outside the weekend sprint. These times must equal the live routine crons (MODEL §8.7 item 12).
**Branch:** `claude/gsc-review-{KEY}-{D}-{T}`. **PR title:** `GSC REVIEW {KEY} {D} [running]`, with the `HELD · ` prefix for portfolio names.

1. **Preflight** per `routines/README.md` §0.
2. **Find what's due.** Build the candidate list in this priority order:
   1. **Held names** (portfolio table) whose `Next review` trigger has fired.
   1a. **Held and IN RANGE review requests** — lines in the `queue/TODO.md` block `▶ Review requests (SWEEP)` for a held name (a changed held zone included: a SWEEP merges with it and the weekly report only lists it, MODEL §8.7 items 10–11, J11), then lines whose reason starts `IN RANGE`; oldest sweep date first within each. These would otherwise wait behind the method re-tests and expire after 4 weeks (critic O2).
   1b. **Method re-tests** — keys listed in the `queue/TODO.md` head blocks `▶ Method re-tests v4.8.0`, `▶ Method re-tests v4.6.0` and `▶ Method re-tests v4.5.0`, read newest first: the v4.8.0 block (Jakub's method decisions of 2026-10-29/30), then the v4.6.0 block (it reopens DNAF names, MODEL v4.6.0, G1–G4), then the v4.5.0 block [v4.8.0]. Held names come first, from all three blocks; then the **partial resumes** [v4.8.0] — every line marked `` — partial {date} (queue/evidence/…)`` in any of the three blocks, every such `▶ Group dependencies` line REVIEW takes (a `parent re-run owed` line, or a `dependency of` line whose key has a stale memo, priority 1c) and every routed `` `KEY` — partial {date} (…) `` item in `queue/TODO.md` (a key with no queue line), oldest partial date first and, on one date, in this priority's own order: the first run left a resumable record that ages, and the second takes it before anything new (MODEL §8.7 item 6; step 4, Resume); then the top line first, block by block in that order. The trigger is the rule change itself. A key on any block takes, in one run, every method rule its prior predates (step 4): the v4.8.0 rules below v4.8.0; Gate 0, the lens, the group rules and the G6 pairing of v4.6.0 below v4.6.0; every v4.5.0 rule below v4.5.0. Appendix G says whether the verdict moved.
   1c. **Group dependencies** (MODEL §2 Group dependencies; P26), in this order:
       - keys of unmarked `▶ Group dependencies` lines whose memo is stale — more than 15 months old, written under a MODEL version below v4.5.0, or a DNAF memo written below v4.6.0 (a listed subsidiary or listed holding a parent read as ungradeable);
       - `` `KEY` — parent re-run owed (HKEY memo {date}) `` lines in the same block, and their `(HKEY retired {date})` and `(HKEY no listed security {date})` forms (INTAKE lists a parent that read a dependency as ungradeable once that dependency's memo lands, or once the dependency is found RETIRED or without a listed security; the re-run grades the part from that memo, or reads it from the parent's own filings, ANALYSE step 5, and several such lines of one parent are one candidate);
       - keys that `python3 routines/tools/gsc_register.py check` lists as `parent stale` (a listed subsidiary's or holding's memo is newer than the parent's, or it has no register row). For `parent stale - holding HKEY … is not current (P26)` (its memo is more than 15 months old or below v4.5.0) the candidate is HKEY itself, not the parent. The parent is never held back by it [v4.6.0; G4]: a parent run that comes first by any priority completes with HKEY ungradeable (WEAK with its weight, nothing added to the look-through Past, no credit: `sub dependency`, `credit owed`) and lists HKEY under its row's `## Group dependency`, so INTAKE queues it in `▶ Group dependencies` (ANALYSE step 5). Once HKEY's memo lands, `check` lists the parent as `parent stale` (holding memo newer).
   2. **Other review requests** in `▶ Review requests (SWEEP)`, oldest sweep date first. Requests carry forward for up to 4 weeks (INTAKE step 3).
   3. **WATCH rows** whose dated trigger (a results date, a filing or an event) is past.
   4. **AVOID rows** whose dated trigger is past. These are low priority by construction.

   Skip a review request (1a, 2) whose key's current memo date (the date in the name of the one file in `memos/{KEY}/`) is on or after the request's sweep date: that name has already been reviewed since. A row's dated trigger is its register `Next review` — a `YYYY-MM-DD` on or before D, or a `Mon YYYY` or `Qn YYYY` whose month or quarter has ended; the memo's `next_review` names the event to check.

   Drop any key that:
   - is claimed (README §2);
   - has a pending `queue/rows/*_{KEY}.md`;
   - already has a current memo dated D (`memos/{KEY}/{KEY}_{D}_GSC.md`);
   - has a `memos/{KEY}/` folder that does not hold exactly one file (name it in the session summary; RECONCILE cleans it up, MODEL §8.5);
   - has a `queue/TODO.md` item `` `KEY` — attended roll-up owed …``, `` `KEY` — attended re-test owed …`` or `` `KEY` — attended group build owed …`` (a routine run overran its budget; Jakub deletes the item after the attended run);
   - is RETIRED (its register Verdict cell reads `RETIRED`; MODEL §7.1 RETIRED: never reviewed), or awaits retirement (a `delisting awaiting retirement` entry for it in `▶ Open items (register)`, or in a dated TODO block where INTAKE routes it when the head block is at its 7-entry cap: the delisting is with Jakub) [v4.6.0; G5];
   - has a `▶ Method re-tests v4.8.0`, `▶ Method re-tests v4.6.0` or `▶ Method re-tests v4.5.0` line, a `parent re-run owed` line or a routed `` `KEY` — partial … `` item marked ` — incomplete {date}: {gap}` with that date less than 14 days before D, or marked `attended re-test owed` or `attended group build owed` (MODEL §8.7 item 6: an INCOMPLETE re-test is retried once after 14 days, a budget overrun is resumed once, then each is left to Jakub; critic B1). A `dependency of …` line marked `[!]` gets no retry from that line (priority 1c takes unmarked lines only; a ` — partial …` marker is not `[!]` and leaves a line unmarked): the subsidiary or holding stays ungradeable for its parent until a memo of it lands (INTAKE step 3, Mark). Example: `` `KCR.HE` — … → re-test (25%) — incomplete 2026-10-20: FY2016 segment notes not retrieved `` is skipped until 2026-11-03; a second INCOMPLETE turns it into `… — attended re-test owed (incomplete 2026-10-20, 2026-11-04)`;
   - has a line or item marked ` — partial D …`, D being this run's date: the first run's record holds the name `queue/evidence/{KEY}_{D}_INCOMPLETE.md`, so the resume waits for the next run date (a weekend-sprint INTAKE can mark a line on the day it overran) [v4.8.0];
   - is a stalled REVIEW key (README §2): it has two abandoned REVIEW PRs closed within 14 days of each other, and the later one was closed less than 14 days ago.

   Priorities 1a–2 need no due-check: their trigger is a price, a rule change or a dependency, so the first candidate that survives the drops is the run's name. For 1, 3 and 4, check at most 4 candidates, in order, to see whether the cited document or event has actually been published. Use one search or IR-page lookup per candidate and log these as "due-check operations". They are the one web work allowed before the claim. The first confirmed candidate is the run's name.

   A due-check that finds the key's listed line has ceased to trade — a take-private or merger has closed, a squeeze-out is registered, or a delisting is effective — drops the candidate (a line that has ceased to trade is never reviewed) and raises an open item, `ADD: KEY — delisting awaiting retirement (§7.1 RETIRED) — {event}, {date}, {source}`, under `## Open items` in this run's row file, or in the session summary when no row file is written. A routine never retires a key: `gsc_register.py retire` is attended only (MODEL §7.1 RETIRED) [v4.6.0; G5].

   If nothing is confirmed, open no PR. End with a session summary listing each candidate checked and why it isn't due. A due-but-unpublished trigger (for example "10-K not yet filed") is worth one line under `## TODO additions` only if a row file is being written anyway.
3. **Claim** before any further research (README §2).
4. **Review.** Follow MODEL §8.2 steps 1–6 exactly, within the P14 REVIEW budget.
   - Load the prior memo per §7.4a: the one file in `memos/{KEY}/` (its filename is `{P_FILE}`, its date P). Confirm its date matches the register row. If it points to an earlier version ("unchanged from v…", "see v…", a memo file name), read the files in `archive/memos/{KEY}/`, newest first, until every pointer is resolved. These are repo reads, never P14.
   - **Resume [v4.8.0].** Before any fetch, read every `queue/evidence/{KEY}_{date}_INCOMPLETE.md` of the key, newest first — the record a partial line or item names, and any earlier INCOMPLETE record — under README §5 Resume:
     - carry a figure without re-deriving it only if its `source` names a primary document and a location in it (accession or URL, plus page, table or note);
     - re-open that source for every **governing figure** — any figure that decides a gate, a grade, the trigger or a zone — and check the figure there before relying on it (primary retrieval, uncounted under P14);
     - re-derive every figure without such a citation, and never carry a labelled assumption;
     - re-read each reading the record settled (B1 record years, the G6 readings, the P20 build, the P17 table, the worth table) on the live rules; its pointers are inputs, never findings;
     - Appendix A lists `carried from evidence {file}: {items}` (and the sources re-opened); Appendix G says the run resumed (`resumed from partial {D1}: {file}`) when a partial marker named the record.
   - Fetch only the delta; reuse every figure the prior chain already holds, and write it out in full (MODEL §6.6). The current price comes from one GET to the key's endpoint symbol (README §5); its `currency` is `px_unit`.
   - Re-test the sections the new information touches, plus any section whose mechanics changed between the prior memo's `model_version` and the live version. **A prior below v4.5.0 is re-tested on every v4.5.0 method rule, a prior below v4.6.0 on Gate 0, the lens, the group rules and the G6 pairing of v4.6.0, and a prior below v4.8.0 on the v4.8.0 rules** (MODEL §8.2 step 3), listed in a `▶ Method re-tests` block or not, as round 2, v4.6.0 and v4.8.0 left them (MODEL §2 tag line: the R and V decisions of 2026-10-07 supersede the matching J-texts; the G decisions of 2026-10-15 and the v4.8.0 decisions of 2026-10-29/30 apply at a name's next run):
     - **Gate 0 (every prior below v4.6.0) [v4.6.0; G1–G4]:** the best sentence the filings allow, and, for a group, the group sentence and one sentence per material part, a part never failing the group; only the P30 line fails — the filings do not show what the company sells, and who pays for it, for more than half of its revenue: incomprehension (disclosed, but not statable in plain words) or obfuscation (withheld), never a judgment of intent or profitability (`Gate 0: FAIL — incomprehension: {parameter}` or `Gate 0: FAIL — obfuscation: {what is withheld}`, §6.4). A prior DNAF on a retired ground — too hard (R4 (a)–(c)), an irreducible unit, a material "Other", a holdings cycle, a failing part or a DNAF holding — runs the full analysis, every gate on the rules below. Then the lens (FI, else STD, with STD's own rules for a bank, insurer or stake-holding company that FI does not fit), captive finance arms consolidated on STD, and, for a group, the unit as the grain of the Future, the weighted grades (P29), the allocation-across-the-parts table (§2·1C·3) and the dependency check.
     - **Past:** the J1 OI line and financial income out; maintenance-capex FCF (P20) in every FCF test, with the all-capex reading beside it; the 10-year and 5-year bars, the harsher-of growth reads, the P3 paths and the J6 decline (a single P28 year never fires limb (b) alone); on STD, every G6 class above the P31 line read exclude-both and include-both, the harsher governing (every prior below v4.6.0) [v4.6.0; G6]. Every prior below v4.8.0 also gets two v4.8.0 rules (MODEL §2·1A) [v4.8.0]:
       - read (ii) governs a growth metric whose read (i) is n.m.;
       - segregated customer funds held safely (cash, bank deposits, money-market funds or government securities maturing within 12 months, as the filer reports them), with their printed obligation, leave CE, deducted once, and L/E: the funds are never cash, the obligation is never a debt-equivalent, and float income reported in revenue stays in OI; funds invested at the company's own risk in other assets stay as built.
     - **Future:** the paying customer; customer and supplier concentration, flagged and judged against the moat (R7: carried by a strong moat at an ADEQUATE cap, otherwise a STRONG force under P16; funding concentration stays strict); supplier evidence, containment and the market-growth cap. In a group, a statement ruling out a customer at 10% of consolidated revenue (or the filer's lower threshold) covers every unit, unless the filer names a concentrated customer or unit or a unit discloses its own concentration (MODEL §2·1B) [v4.8.0].
     - **SF**, read on the §2·1C ladder: the hairiest pay number against the P17 flag and egregious-strike lines; the director cap; the P23 alignment call and votes versus economics, as inputs (no pledge flag); the glaring RPT; the worth test on maintenance-capex FCF, with the sterilisation floor; and the acquisition stop (J14, V1). For every prior below v4.8.0 (MODEL §2·1C·3) [v4.8.0]:
       - each tranche-year is read at the point of purchase, on the trailing-3-FY reads published before it (at the window's opening, the latest annual report before it; none published, INDETERMINATE (b)), holding credits and the FI read on the same terms, the year read printed beside and never governing;
       - the ≈ 1% floor is tested per fiscal year, never summed;
       - an after-tax or post-amortisation acquiree profit is grossed up to the OI basis only for a charge it bore (tax on an after-tax figure; the deal's amortisation on a post-acquisition or pro-forma figure that includes it, never on a pre-deal one), where the rate or amount is printed.
     - **Gate 2:** the debt-equivalents (a listed subsidiary's NCI at the higher of market and book); the securities classes; holding credits at the holding's own intrinsic value (V14); the P28 down-year test; the 3-year and 5-year readings; the lens's own band; and the trigger at the no-cash bound (R10).

     The TODO line's notes are pointers, never findings. A note written before round 2 (a SOTP or SOTP-DOUBT reading, a part grade, a waiver, a pledge flag, an all-cash trigger) is read under the rules above. A note written before v4.6.0 (a too-hard reason, an irreducible unit, a projected DNAF) is read the same way. Appendix G says which rules moved what.
   - **Lens, groups and the round-2 method steps**, exactly as ANALYSE step 5:
     - Gate 0 is the best sentence the filings allow, failing only at the P30 line, on incomprehension or obfuscation (the §6.4 ground line); then the lens: FI, else STD, on STD's own conservative rules for what the retired too-hard pile stopped.
     - For a group: Group Gate 0 (a part never fails the group); the unit as the grain of the Future; the dependency check; the weighted grades; the allocation-across-the-parts table in Appendix E; and the holding credits. A dependency whose memo is missing, stale (a DNAF memo below v4.6.0 included) or DNAF, whose line is marked `[!]` in `▶ Group dependencies`, or whose venue the endpoint does not serve counts WEAK with its weight in the weighted Future, adds nothing to the look-through Past and earns no credit (`sub dependency`, `credit owed`): a non-controlled one is read as a G6 class throughout (an equity-accounted one as an associate, any other as S3), on the G6 readings in Gate 1A (ANALYSE step 5, the G6 pairing; P31) [G6], as is a holding read on FI, and any holding for a year its memo's B record lacks (MODEL §2·1A guard (ii)), and its SF is INDETERMINATE (b) for the parent. The run completes, and each one whose memo is missing or stale goes under the row file's `## Group dependency` [v4.6.0; G4]. Past is never weighted (MODEL §2·1A Groups).
     - Then the P20 build; the G6 income–capital pairing on STD [v4.6.0; G6; P31]: the closed list of classes (associates and JVs with their long-term interests, H excepted; S3 stakes, securities and non-operating loans; an insurance activity's whole investment portfolio), the P31 test (the classes summed and tested together), and, above the line, the B2 per-year series and summary rows and the B3 growth reads on both readings, the harsher governing in Gate 1A only, logged in Appendix C (a prior below v4.6.0 kept the class's capital in CE with its income out, the pairing G6 retired: both readings are built over the window, and Appendix G says whether Past moved); then the P28 test, the R7 worksheet, the pay, director and alignment worksheets, the averaged readings, and the trigger at the no-cash bound.
   - **Budget overrun — two-run resume (MODEL §8.7 item 6) [v4.8.0].** A group build that cannot finish within the time budget stops with `INCOMPLETE (group build exceeds budget)`; a v4.5.0, v4.6.0 or v4.8.0 method re-test that cannot finish stops with `INCOMPLETE (method re-test exceeds budget)`. Stop in time to write the evidence file as a **resumable record** (README §5): the header, every figure gathered in the item table with its primary document and location, the readings settled, and the scope still owed as a checklist — the next run starts from it, not from zero.
     - **First overrun** — `queue/TODO.md` marks no line or item of this key ` — partial …` (README §5: only open lines and items count; a closed DRAFT_QUEUE line's note is history): `## TODO additions` carries no `attended … owed` item. INTAKE marks the key's re-test lines ` — partial {D} (queue/evidence/{KEY}_{D}_INCOMPLETE.md)`, or routes that as a `` `KEY` — partial … `` item for a key with none (INTAKE.md step 3), and the next REVIEW on a later date takes it first (step 2, 1b).
     - **Second overrun** — this run resumed a partial dated D1: `## TODO additions` carries `` `KEY` — attended group build owed (REVIEW {D}; partial {D1}) `` or `` `KEY` — attended re-test owed (REVIEW {D}; partial {D1}) ``, then what is still owed, naming both records (`queue/evidence/{KEY}_{D1}_INCOMPLETE.md`, `queue/evidence/{KEY}_{D}_INCOMPLETE.md`). INTAKE turns the line's partial marker into the attended one with both dates, and REVIEW skips the key until Jakub deletes the item after the attended run.
   - **Held names** also get step 4: the sell-reason audit, the current zone with distances to the ADD band and the sell-flag line, and the bias tick-through before the zone statement (MODEL §7.2).
     - The ADD band is the trigger, the no-cash bound (P21, R10). The memo's `add_band` equals its `trigger`, and the zone is ADD only at or under it (with the other §7.2 ADD conditions).

   - **Legacy roll-up.** If the complete memo (MODEL §6.6) can't be finished within the time budget (README §5), stop with `INCOMPLETE (roll-up exceeds budget)` and add `` `KEY` — attended roll-up owed (REVIEW {D}, prior {P_FILE}) `` under `## TODO additions` in the row file.
5. **Write:**
   - **Memo:**
     - the new memo `memos/{KEY}/{KEY}_{D}_GSC.md`: one complete, self-contained memo per MODEL §6.6 — full front matter, body and Appendices A–G, folding the prior findings and the new evidence into one current analysis. Front matter: `memo_date: {D}`; `memo_version: v{n+1}`, where n is the number in the prior's `memo_version` (if it has none, n = the number of files in `archive/memos/{KEY}/` + 1); `supersedes: archive/memos/{KEY}/{P_FILE}`; the live `model_version`; `produced_by: ROUTINE`; `run_base: {sha}`.      - `queue/rows/{D}_{T}_REVIEW_{KEY}.md` (README §4) with the replacement row, plus the portfolio row if the name is held, both pasted from `python3 routines/tools/gsc_register.py row-from-memo memos/{KEY}/{KEY}_{D}_GSC.md --table`, and, for a group, `## Group dependency` (step 4)

INTAKE marks the key's `▶ Method re-tests v4.8.0`, `▶ Method re-tests v4.6.0` or `▶ Method re-tests v4.5.0` line, `parent re-run owed` line or `▶ Group dependencies` line from the title's named gap (` — partial {D} (…)` for a first budget overrun; INTAKE.md step 3).

7. **Stop.** One name per run.

**Forbidden:**
- a second name
- any edit to the register, TODO, the queue or IDEAS
- position events: a "bought" or "sold" line in any source never becomes a portfolio change here
- any edit to the prior memo, and any change under `archive/` other than the one move in step 5
- any change to a locked path
