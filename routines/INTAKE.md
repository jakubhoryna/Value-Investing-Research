# INTAKE routine — the single register writer (MODEL §8.7; §7.4a and §7.5 in git form)

**Schedule:** daily at 06:00 Europe/Prague, plus a sprint run on Saturday at 18:00.
Weekdays 09:00–18:00 are routine-free and 02:00–06:00 is quiet outside the weekend sprint. These times must equal the live routine crons (MODEL §8.7 item 12).
**Branch:** `claude/gsc-intake-{D}-{T}`. **PR title:** `GSC INTAKE {D} [running]`.

INTAKE folds everything Jakub has **merged** since the last intake into one register version. On `main`, the files in `queue/rows/` and `queue/proposals/` (other than `README.md`) are by definition merged and pending. INTAKE does no web work. It also runs the daily abandoned-claim sweep and the free-plan audit, and refreshes the private register page best-effort (step 9).

Work in the working tree and stage nothing until step 9; that keeps the restart in step 8 clean. Every register computation runs through `routines/tools/gsc_register.py` (MODEL §7.1, §7.1b; README §5): `apply` in step 3, `render` in step 4, `check` in step 7. `_REGISTER.md` and `register.csv` are never edited by hand.

0. **Preflight** per `routines/README.md` §0. Then, in this order:
   - **Abandoned-claim sweep** for all jobs, INTAKE included (README §2): close every `[running]` PR not updated for more than 6 h with the abandoned-close PATCH. Then re-run the ledger command (README §1), so the PRs just closed count, and find stalled keys from it. This cleanup runs even when a later bullet stops the run (F1).
   - **Stall watchdog.** Count the open routine PRs whose title ends neither `[running]` nor `[fixing]` and whose `updated_at` is more than 24 h old. Read the newest digest's creation time: `gh api "repos/jakubhoryna/Value-Investing-Model/issues?state=all&creator=github-actions%5Bbot%5D&sort=created&direction=desc&per_page=100" --jq '[.[] | select(.pull_request == null and .user.login == "github-actions[bot]" and (.title | test("^(STALL - )?GSC digest ")))][0].created_at // "-"'`. If the count is above 15, or the newest digest is more than 30 h old or missing, send one push (README §5): `GSC STALL · INTAKE {D} · PR - · {count} finished routine PRs waiting > 24 h; last digest {h} h ago`. Compare times in UTC.
   - **Open INTAKE PR.** If an open `GSC INTAKE` PR is still open after the sweep:
     - its title ends `[fixing]` → stop with no PR (Jakub is repairing it);
     - it is finished (its title has ` — ` and ends neither `[running]` nor `[fixing]`) and its `updated_at` is more than 20 h old → close it with the supersede PATCH (README §1) and continue (F2): its row and proposal files are still pending on `main`, so this run applies them;
     - otherwise → stop with no PR (it is still running, or gsc-automerge or Jakub will merge it).
   - **Nothing to do** means all of these hold:
     - no pending row file, other than rows that would be held back again (their memo is still missing on `main`, or their key's `memos/{KEY}/` does not hold exactly one file, step 3);
     - no pending proposal;
     - no unrecorded closed-unmerged or reverted ANALYSE PR, meaning none that step 5 would record (its key has a `[ ]` line and its number appears nowhere in `queue/DRAFT_QUEUE.md`);
     - no stalled key still to record, meaning none that step 5 or step 6 would record (README §2).

     Then stop with no PR and end with a session summary.

   Name every PR closed in this step (`[abandoned]`, `[superseded]`) and any held-back rows in the session summary and, when the run goes on, in the PR body; the closing title is each closed PR's record (no comment).
1. **Base.** Record the HEAD sha; the outgoing register's `register_version` N and `register_date`; the TODO version n and date; the DRAFT_QUEUE version n and date. A version is the number after `v` in the file's version line. The next version is the next whole number: v36 → v37, and a dotted v1.1 → v2. Claim the branch and PR (README §2).
2. **Audit** (free-plan compensating control). Re-run the ledger command (README §1) first, so it includes this run's own PR. For the PR body, under `## Audit`:
   - commits on `origin/main` since the previous `GSC INTAKE` PR's `merged_at` (on the first run, the last 7 days) that didn't arrive through a PR merge: `git log --first-parent --since="<merged_at>" --format='%h %s' origin/main`. A subject that ends with `(#<n>)` (squash merge) or starts with `Merge pull request #<n> from ` (merge commit) is a PR merge; anything else is a direct commit. A rebase merge also shows up here as direct commits, so routine PRs are merged with "Squash and merge" or "Create a merge commit", never "Rebase and merge".
   - `claude/gsc-*` branches with no PR in the ledger: `git ls-remote origin 'refs/heads/claude/gsc-*'`. Leave out this run's own branch.
   - changes under `archive/` other than additions (MODEL §7.5: append-only): `git log --first-parent --since="<merged_at>" --no-renames --diff-filter=MD --name-status --format='%h %s' origin/main -- archive/`. List each one. A commit whose subject starts `GSC: RECONCILE` (re-key), `GSC: MODEL` (framework release) or `Revert "` (Jakub's undo of a merged PR) is expected; any other is an archive breach.

   A subject starting `Revert "GSC ANALYSE {KEY} ` or `Revert "GSC REVIEW {KEY} ` (Jakub's undo of a merged PR, MODEL §8.7 item 10) is a PR merge, not a direct commit. Record it: ANALYSE → step 5 marker; REVIEW → a TODO item `` `KEY` — REVIEW reverted {D} (PR #n) `` (n = the reverted PR's number), unless that number already appears in `queue/TODO.md`.

   The lean ledger leaves out old closed PRs: before listing a `claude/gsc-*` branch as having no PR, confirm it with `gh api "repos/jakubhoryna/Value-Investing-Model/pulls?state=all&head=jakubhoryna:{branch}" --jq length` (0 = no PR).

   If any direct commit or archive breach exists, add a TODO item naming it.
3. **Apply the row files, oldest `run_date` then `run_time` first.** First `cp register.csv /tmp/register_outgoing.csv` (the outgoing bytes, for the step-4 snapshot). The register rows are applied here with the tool, which updates `register.csv` only; everything else in step 3 only collects changes (in `/tmp` notes): do not edit `_REGISTER.md`, `queue/TODO.md` or `queue/DRAFT_QUEUE.md` until its archive copy is taken (steps 4–6).
   - **ANALYSE / REVIEW.**
     - Let CUR be the files in `memos/{KEY}/` on `main` (`git ls-tree --name-only HEAD -- memos/{KEY}/`). Never pick a memo by date.
     - If CUR is exactly one file and it is `memo_path`: build the row from it (the `Apply it` bullet below).
     - Else, if `archive/{memo_path}` exists on `main`, the row is **superseded** (a newer REVIEW moved its memo to the archive): apply only its `## Queue update`, consume the file, and log "superseded by {the one file in CUR}".
     - Otherwise **hold back** the row (its memo is not on `main`, or CUR does not hold exactly one file): leave the file in place, list it under `## Held back` in the PR body with the reason, and apply nothing from it. If CUR holds more than one file, also add the TODO item `` `KEY` — memos/{KEY}/ holds {n} files; attended clean-up moves all but the current one to archive/memos/{KEY}/ `` (→ step 6), unless `queue/TODO.md` already has an item `` `KEY` — memos/{KEY}/ holds …``.
     - Apply it: `python3 routines/tools/gsc_register.py apply --row {file}`. The tool builds the row from the one file in CUR (README §4, memo wins: front matter only), places it in its §7.1 section and order (a REVIEW replaces the key's row, moving section if the verdict changed; an ANALYSE adds a new name) and prints a JSON report. Paste its old → new rows into the PR body. Its `BACKFILL` lines become one step-6 TODO addition per key, `` `KEY` — backfill: {fields} — fill at the next REVIEW ``; its `NORMALISED`, `NOTE` and `LEGACY` lines go into the PR body (`LEGACY`: a memo written before v4.5.0 has no machine fields, so the tool reads its price, trigger, next review, printed multiples and Past level from its text, as the one-time rebuild did).
     - Held name: the tool takes zone, ADD band and sell line from the memo and keeps the held flag and `avg_cost`. It never sets or clears the held flag: a `HELD-MISMATCH` line (memo `position` ≠ register) becomes an open item `ADD: KEY — memo position ≠ register held flag; position event for Jakub` (→ step 6). Never add or remove a portfolio row.
   - **INCOMPLETE / PRIOR / QUEUE.** No register change. Their `## Group dependency` and `Group dependency:` lines, and the re-test markers, go to step 6 (below).
   - **SWEEP.** `python3 routines/tools/gsc_register.py apply --row {file}`. The tool applies each `## Price/ordering refresh` line under MODEL §7.1 and §7.1b: Px, `px_date` and `px_source`, then MCap/FCF and EV/OI and their 3-year and 5-year readings recomputed from the core numbers and the constant holding credit (with the row file's `## FX` rate where the pair matches), and, for a held name, `Last zone check` only when the row file's `## Portfolio table` zone equals the Portfolio `Zone` (MODEL §7.2, J11: a changed held zone keeps the date and the tool says so in a change note; list each such key under `## Held zone changes` in the PR body — the SWEEP's own review request carries it to REVIEW). It skips a key that is out of SWEEP scope (two-or-more-gate AVOID or DNAF, not held), whose close is not later than the row's `px_date`, whose row comes from a memo dated after the close, or whose `Px unit` differs from the row's `px_unit` (a row with `px_unit` `-` takes the endpoint's currency). Zone, trigger and verdict never change from a sweep. Paste the tool's skip list and the sweep's `## Unit or instrument mismatches` into the PR body.

     → step 6: **merge** this sweep's `## Review requests` into the TODO block `▶ Review requests (SWEEP)`; requests carry forward until reviewed or 4 weeks old (F3):
     - start from the block's current lines;
     - drop a line whose key's current memo date is on or after the line's sweep date (reviewed), or whose sweep date is more than 28 days before D (expired; list the expired keys in the PR body);
     - for each requested key, replace an existing line for that key, or append a new line `` - `KEY` — reason — sweep {run_date} ``; leave out a key whose current memo date is on or after the sweep's run_date;
     - keep the remaining lines in their order.
   - **Every row type**, unless held back (a superseded row: `## Queue update` only):
     - `## Queue update` → step 5.
     - `## TODO additions` → step 6.
     - `## Open items` → step 6: apply to the TODO head block `▶ Open items (register)` under MODEL §7.1: two classes only (pending user decisions, register-integrity holds), one line each, at most 7 entries. Never remove a pending user decision; you may update its text. An entry that doesn't fit the classes or the cap goes to the dated TODO block instead, and the PR body says so.
     - `## IDEAS candidates` → step 6: copy verbatim into the TODO head block `▶ IDEAS candidates (attended triage)`, each line prefixed `{run_date} · {KEY} {JOB} —`.
   - **Group dependencies → step 6** (MODEL §2 Group dependencies; §8.7 item 6). The head block `▶ Group dependencies` holds one line per material listed subsidiary or listed holding a parent waits on, `` - `HKEY` — dependency of PARENT (run {D}) ``, plus `` - `PARENT` — parent re-run owed: dependencies cleared {D} `` lines. INTAKE adds, marks, rewrites and removes lines as below, appending markers after ` — `, and never reorders the block. "Current" means the one memo in `memos/{KEY}/`, dated no more than 15 months before D and written under MODEL v4.5.0 or later (MODEL §2 Group dependencies).
     - **Add.** Each `## Group dependency` line of an INCOMPLETE row of PARENT becomes `` - `HKEY` — dependency of PARENT (run {run_date}) ``, unless a line for the same HKEY and PARENT is present.
     - **Remove on a landed memo.** A merged ANALYSE or REVIEW memo of KEY (applied above, not INCOMPLETE) at v4.5.0 or later removes every line whose key is KEY (the subsidiary or holding is now current), every `dependency of KEY` line and the `` `KEY` — parent re-run owed `` line (the parent itself landed).
     - **Mark.** An INCOMPLETE row of KEY whose key has an unmarked dependency line appends ` — [!] incomplete {run_date}: {gap}` to it, {gap} being the named gap in the row's `pr_title`. A stalled ANALYSE key (README §2, step 5) with an unmarked dependency line appends ` — [!] stalled {D} (PR #a, #b)`, only if `#b` appears nowhere in `queue/TODO.md`. A marked subsidiary or holding is ungradeable: the parent counts it WEAK with its weight in the group grades, with no credit (`sub dependency`), and completes (ANALYSE.md step 5).
     - **Rewrite.** A row's `## Queue update` line `Group dependency: KEY → prior KEY2` rewrites that line's key to `KEY2` and appends ` (prior of KEY)`, or removes the line when KEY2's memo is current. `Group dependency: KEY → memo exists` removes the line when KEY's memo is current and otherwise leaves it for REVIEW priority 1c.
     - **Parent re-queue.** After every row file is applied: for each PARENT one of whose dependency lines this run removed or marked, if no unmarked `dependency of PARENT` line remains and PARENT's memo did not land in this run, re-queue it once. A `queue/DRAFT_QUEUE.md` line of PARENT marked `[!] incomplete …` resets to `[ ]` with ` — retry (dependencies cleared {D})` appended (step 5). Otherwise (a REVIEW parent) add `` - `PARENT` — parent re-run owed: dependencies cleared {D} `` unless present, and drop a ` — incomplete {date}: dependency…` marker from PARENT's `▶ Method re-tests v4.5.0` line. The `[!]` lines of PARENT stay until PARENT's memo lands: the parent run reads them.
     - *Worked example (illustrative).* A REVIEW of `INVE-B.ST` ends `INCOMPLETE (dependency: AZN.L)`, its row naming `AZN.L` and `SEB-A.ST` → two lines `` `AZN.L` — dependency of INVE-B.ST (run 2026-10-20) `` and `` `SEB-A.ST` — … ``, and its `▶ Method re-tests v4.5.0` line gets ` — incomplete 2026-10-20: dependency: AZN.L`. ANALYSE takes `AZN.L` next; its memo lands → that line goes. `SEB-A.ST`'s ANALYSE ends INCOMPLETE → its line ends ` — [!] incomplete 2026-10-22: data access`. No unmarked line of `INVE-B.ST` remains → `` `INVE-B.ST` — parent re-run owed: dependencies cleared 2026-10-23 `` is added and the re-test marker dropped; REVIEW takes it at 1b, counting `SEB-A.ST` WEAK with its weight in the group grades, with no credit (`sub dependency`). When `INVE-B.ST`'s memo lands, its `▶ Group dependencies` lines and its re-test line go.
   - **Re-test markers → step 6** (MODEL §8.7 item 6; critic B1). An INCOMPLETE REVIEW row of KEY whose key has a `▶ Method re-tests v4.5.0` line or a `parent re-run owed` line: for the named gaps `group build exceeds budget` and `method re-test exceeds budget` add nothing here (the row's `attended … owed` TODO addition makes REVIEW skip the key). For any other gap, a line without a marker gets ` — incomplete {run_date}: {gap}` (REVIEW skips the key for 14 days); a line that already carries one ends instead ` — attended re-test owed (incomplete {first date}, {run_date})` (REVIEW skips the key until Jakub clears the marker).
   - **REVIEW applied** → step 6: remove its key from `▶ Review requests (SWEEP)` when the REVIEW's run_date is on or after that line's sweep date. When the REVIEW wrote a memo (not INCOMPLETE) whose `model_version` is v4.5.0 or later, also remove its key's line from `▶ Method re-tests v4.5.0` and from every `▶ Backfill owed — …` block (`register rebuild …` and `retrigger …`): that memo applied the codified rules, carries every v4.5.0 field and states its trigger at the no-cash bound (`trigger_basis: no-cash`; lint-memo). A memo written under an earlier version (a run that started before the release) leaves those lines in place.
4. **Regenerate the register (§7.4a generation rule)** — only if step 3 changed at least one register row (a tool report with changes; `register.csv` then differs from `main`). A change to the open items alone makes no register version (they live in TODO). Otherwise write no snapshot and no new version; queue and TODO changes still go ahead.
   - **Snapshot first.** `mkdir -p archive/registers/{YYYY}`, then `cp _REGISTER.md archive/registers/{YYYY}/REGISTER_v{N}_{register_date}.md` and `cp /tmp/register_outgoing.csv archive/registers/{YYYY}/REGISTER_v{N}_{register_date}.csv`, where YYYY is the year of the outgoing `register_date`. They are byte copies of the outgoing files: never write them with the Write tool. If either path already exists on `main`, something else wrote the register: treat it as an unfixable breach (step 7).
   - **Render:** `python3 routines/tools/gsc_register.py render --version v{N+1} --date {D}`. The tool writes the complete `_REGISTER.md` — front matter (version, date, `names_total`, `verdict_split` and `portfolio_names` derived from the rows), legend, PORTFOLIO, BUY, WATCH, AVOID one gate, AVOID two+, DNAF (the master tables with the two averaged columns, `MCap/FCF 3y · 5y` and `EV/OI 3y · 5y`), sorted by EV/OI — and refuses a cell over 160 characters, an AVOID row with no failed gate, a duplicate key or an unknown section.
   - The version's one-line entry, ≤ 200 characters — `v{N+1} — {D} — INTAKE: KEY ANALYSE VERDICT (gate); KEY REVIEW …; SWEEP refresh ({k} Px)` (keys only if it doesn't fit) — goes into the commit body, the PR body and the run note. The register keeps no change log.
5. **Update `queue/DRAFT_QUEUE.md`** — only if something changes. First `cp queue/DRAFT_QUEUE.md archive/queue/DRAFT_QUEUE_v{n}_{date}.md` (the outgoing version and its date). Markers replace only the leading token and keep `KEY — Company — …`. A marker is set only on a line whose marker is `[ ]` at that moment, counting changes made earlier in this INTAKE. It never overwrites another marker, so a later prior marker can't replace `[x] {D}`. List any skipped update in the PR body.
   - `[ ]` open · `[x] {D}` analysed (merged ANALYSE row) · `[x] prior — REVIEW` (PRIOR row or queue marker)
   - `[-] rejected {D} (PR #n)` — for each closed-unmerged PR titled `GSC ANALYSE {KEY} {date} …` whose key has a `[ ]` line and whose number appears nowhere in the file. Skip titles ending `[abandoned]`, `[superseded]` or `[running]`, `— prior found (REVIEW)` and keyless `queue exhausted` PRs.
   - `[-] rejected {D} (PR #n, reverted)` — for each step-2 revert of a merged `GSC ANALYSE {KEY} …` PR (n = the reverted PR's number) whose key has an `[x]` or `[ ]` line and whose number appears nowhere in the file. This marker may replace `[x] {date}` for that key, because the memo is gone.
   - `[!] incomplete {D} — {evidence_path}` (INCOMPLETE row)
   - `[!] stalled {D} (PR #a, #b)` (README §2) — only if the later number, `#b`, appears nowhere in the file.
   - `[ ] … — retry (dependencies cleared {D})` — the step-3 parent re-queue resets a group parent's `[!] incomplete {D0} — {path}` line to `[ ]` and appends the note (MODEL §2 Group dependencies). It is the only marker INTAKE ever takes back to `[ ]`.

   "Appears" means as a whole number: `#44` doesn't match `#445`.

   Append the section 6 `DRAFT_QUEUE restock` lines of each pending `*_QUEUE-SEED.md` below the last queue line (above the footer note), skipping any key already present with any marker; list skipped lines in the PR body. Never reorder lines. Bump the version line to `(v{next} · {D})`, `{next}` per step 1.
6. **Update `queue/TODO.md`** — only if something changes. First `cp queue/TODO.md archive/queue/TODO_v{n}_{date}.md` (the outgoing version and its date). Then:
   - The four standing head blocks sit first, below the purpose paragraphs: `## ▶ Review requests (SWEEP)`, then `## ▶ IDEAS candidates (attended triage)`, then `## ▶ Open items (register)` (MODEL §7.1: pending user decisions and register-integrity holds, one line each, at most 7), then `## ▶ Group dependencies` (MODEL §2 Group dependencies; INTAKE maintains it, step 3, and writes `None.` when it holds no line). Create them if absent, then apply the head-block changes collected in step 3. INTAKE never clears IDEAS candidates (attended triage does) and never removes a pending user decision from Open items.
   - The attended blocks follow them while they hold lines: `## ▶ Method re-tests v4.5.0`, `## ▶ Backfill owed — register rebuild …` (MODEL v4.5.0 build) and `## ▶ Backfill owed — retrigger …` (round 2: rows whose trigger is still the pre-R10 all-cash reading, MODEL §7.1). INTAKE never creates, reorders or adds to them: it removes a key's line when that key's REVIEW memo lands and marks a re-test line on an INCOMPLETE REVIEW (step 3); an empty block is deleted by an attended session.
   - Add one dated block below them, `## ▶ Routed by INTAKE {D}, register v{N+1}` (or "register unchanged"), with the `## TODO additions`, grouped by key, each item starting with the backticked key. Add the audit items here too, and a stalled-REVIEW item `` `KEY` — REVIEW stalled {D} (PR #a, #b) `` only if the later number, `#b`, appears nowhere in `queue/TODO.md` (README §2).
   - Bump the version line to `(v{next} · {D})`, `{next}` per step 1, and prepend one line to `## Change log` in the file's own style, naming the archive.
7. **Checks — by the tool and by script, not by eye.**
   - `python3 routines/tools/gsc_register.py check --base {step-1 sha}` exits 0. Paste its output. It checks: the `register.csv` header (lean-2; an older header is read only at the base), UTF-8 and LF line ends; every row's fields (one-word verdict and grades, the reason vocabulary, numbers, `px_unit`, `next_review_short`, the held fields, `trigger_basis` — no-cash for a memo written under v4.5.0 or later — and a held trigger at the no-cash bound equal to its ADD band); no duplicate key; the rendered order; that `_REGISTER.md` is exactly the rendering of `register.csv` (so `names_total`, `verdict_split`, `portfolio_names`, section counts, the 160-character cap and the order all hold); that the multiples of every row with core numbers, the averaged readings included, recompute from them (exactly after a SWEEP or the rebuild; a memo's own print at its own price within 0.1); that every key of the outgoing register is still present; no duplicate ISIN (the `isin` column); every `memos/*/` folder holds exactly one file; and every row's `memo_path` is the one file in `memos/{KEY}/`.
   - `BREACH` lines are breaches: every format rule, and the folder, memo and ISIN findings on rows changed in this version. The group finding `parent stale` is always `LIST` and goes into the PR body only, never into TODO: REVIEW reads it from `check` at priority 1c. The other `LIST` lines are the same findings on untouched rows (a reverted REVIEW, a held-back row, an attended clean-up owed, a legacy duplicate ISIN): they go into the PR body under `## Register findings` and become one TODO item per key — `` `KEY` — memos/{KEY}/ holds {n} files; attended clean-up moves all but the current one to archive/memos/{KEY}/ ``, `` `KEY` — register memo date {date} ≠ current memo {file} ``, `` `KEY` — memo_path {path} missing on main `` or `` `KEY` — duplicate ISIN {isin} with {KEY2} `` — unless `queue/TODO.md` already has an item starting with the same words up to the first number or path.
   - By a `/tmp` script (run with `python3`): the `▶ Open items (register)` block of the new `queue/TODO.md` holds at most 7 entries, one line each; the version's one-line entry (step 4) is ≤ 200 characters (characters, not bytes).

   Fix any breach and re-run. **Unfixable:** throw away the uncommitted changes, commit only the run note naming the breach, push, close your own PR titled `GSC INTAKE {D} — blocked: {reason}` (one PATCH with `state=closed`, title and body), and stop.
8. **Base check.** `git fetch origin main`. If `origin/main` has moved since step 1 and the move touched `_REGISTER.md`, `register.csv`, `queue/TODO.md`, `queue/DRAFT_QUEUE.md`, `archive/registers/` or `archive/queue/` (the INTAKE base paths gsc-automerge checks before merging, MODEL §8.7 item 10), or deleted a file under `queue/rows/` or `memos/` (`git diff -M --diff-filter=D --name-only {step-1 sha} origin/main -- queue/rows queue/proposals memos archive/memos archive/queue/proposals` is not empty: a revert; both sides of a move are in the pathspec, so a REVIEW's move to `archive/memos/` pairs as an exact rename and does not count, however different the new memo is), **restart once** on the same branch and PR. Never re-claim.
   1. Throw away the uncommitted work: `git checkout -- _REGISTER.md register.csv queue`, and `rm` the snapshot and archive files you created (they are untracked; never `rm` a tracked file under `archive/`).
   2. `git merge --no-edit origin/main`.
   3. Redo steps 1–7 (without the claim) from the merged tree.

   On a second collision, close the PR as blocked (step 7) with reason "main moved twice".
9. **Consume, commit, push.**
   - `git rm` each applied or superseded row file. Leave held-back rows.
   - For each applied proposal: `mkdir -p archive/queue/proposals`, then `git mv queue/proposals/{name}.md archive/queue/proposals/{name}.md`. Don't edit it first.
   - **Register page (best-effort; MODEL §7.4).** Only when step 4 wrote a register version, and after the step-8 base check holds. Render the third-party page from the working tree: `python3 routines/tools/gsc_site.py render --out /tmp/gsc-register-page.html`. The page is generated, never stored: it stays in `/tmp`, is never staged and is not part of the PR diff. Then, if this session has the Artifact tool, read `https://claude.ai/artifact/FnU69xTYSTMEjqHB21rVPs` (`action: "read"`, `url`, nothing else) and publish the rendered file, unedited, to that url (`action: "publish"`, `url`, `file_path: "/tmp/gsc-register-page.html"`, nothing else). It is an update in place: never a new artifact, a delete, a capability, an icon or a sharing change (the guard hook refuses each). Write one line in the run note: `register page: published (register v{N+1})`, or, if the render fails or the tool is missing, refuses or errors, `register page: not published - {reason}`. The step never fails, stops, retries or waits; it never changes the PR title, the outcome or the commit, and it sends no push.
   - Write the run note `queue/runs/{D}_{T}_INTAKE.md`. `git add` the exact paths you changed — with a register version always both `_REGISTER.md` and `register.csv` and both snapshots — then commit: `GSC: register v{N+1} — INTAKE {D}` with the version's one-line entry as the commit body, or `GSC: INTAKE {D} — no register change` (this form also covers a run that only consumed files).
   - `git push -u origin "{BR}"` (a fast-forward, also after a restart merge) and finish the PR (README §1) as `GSC INTAKE {D} — register v{N+1} ({k} rows)`, or `GSC INTAKE {D} — no register change ({k} rows)`. gsc-automerge merges it if nothing INTAKE reads or writes moved on `main` meanwhile; otherwise it is held, and the first INTAKE that finds it more than 20 h old supersedes it (step 0). A `blocked:` close (step 7) sends one `BLOCKED` push (README §5).

   The PR body contains every old row → new row, queue changes, TODO changes (group dependency lines added, marked, rewritten or removed, parents re-queued, re-test markers, backfill lines removed), the compliance numbers, memo-vs-row disagreements, superseded rows, `## Held back`, `## Held zone changes` (step 3), the PRs closed in step 0 (`[abandoned]`, `[superseded]`), stalled keys, reverts recorded and `## Audit`.
