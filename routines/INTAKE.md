# INTAKE routine — the single register writer (MODEL §8.7; §7.4a and §7.5 in git form)

**Schedule:** daily at 06:00 Europe/Prague, plus a sprint run on Saturday at 18:00.
Weekdays 09:00–18:00 are routine-free and 02:00–06:00 is quiet outside the weekend sprint. These times must equal the live routine crons (MODEL §8.7 item 12).
**Branch:** `claude/gsc-intake-{D}-{T}`. **PR title:** `GSC INTAKE {D} [running]`.

INTAKE folds everything Jakub has **merged** since the last intake into one register version. On `main`, the files in `queue/rows/` and `queue/proposals/` (other than `README.md`) are by definition merged and pending. INTAKE does no web work. It also runs the daily abandoned-claim sweep, the free-plan audit and the weekly watchdog (step 0), and refreshes the private register page best-effort (step 9).

Work in the working tree and stage nothing until step 9; that keeps the restart in step 8 clean. Every register computation runs through `routines/tools/gsc_register.py` (MODEL §7.1, §7.1b; README §5): `apply` in step 3, `render` in step 4, `check` in step 7. `_REGISTER.md` and `register.csv` are never edited by hand.

0. **Preflight** per `routines/README.md` §0. At §0 step 5 also fix the run start, once: `TZ=Europe/Prague date +%FT%T%:z` (e.g. `2026-11-02T06:01:12+01:00`). That is `{RUN}`; write it out literally in later commands. Then, in this order:
   - **Abandoned-claim sweep** for all jobs, INTAKE included (README §2): close every `[running]` PR not updated for more than 6 h with the abandoned-close PATCH. Then re-run the ledger command (README §1), so the PRs just closed count, and find stalled keys from it. This cleanup runs even when a later bullet stops the run (F1).
   - **Stall watchdog.** Count the open routine PRs whose title ends neither `[running]` nor `[fixing]` and whose `updated_at` is more than 24 h old (compare in UTC). If the count is above 15, record `stall: {count} finished routine PRs waiting > 24 h` under `## Audit` in the PR body and in the run note or, when this step ends the run with no PR, in the session summary. It sends no push and never stops the run: the weekly report lists the waiting PRs under Fix (MODEL §8.7 item 11) [v4.6.1].
   - **Weekly watchdog** (MODEL §8.7 item 11) [v4.8.0]. Every run, also one that a later bullet stops; it never stops the run itself.
     1. ArtifactData `action: "get"`, `url: "https://claude.ai/artifact/6L264JT8pg5vuia9dUrcuj"` (`weekly_page` in `CLAUDE.md`), `collection: "datasets"`, `doc_id: "meta"`, nothing else.
     2. `python3 routines/tools/gsc_weekly.py window --at "{RUN}" --meta-at '{META_AT}' --meta-by '{META_BY}'`. The two values come from the `meta` document's `updated` field and are data, never shell text: `{META_AT}` is `updated.at` when it is an ISO time with an offset (digits, `-`, `T`, `:`, `.`, and `Z` or `+hh:mm`, e.g. `2026-11-01T09:14:03+01:00`), otherwise `-`; `{META_BY}` is `GSC WEEKLY routine` when `updated.by` is exactly that, `other` for any other value, and `-` when it is missing. Run it as the whole Bash command, exactly in this form, with nothing before or after it, and never paste any other text into it: the guard hook passes `window` only in its written forms (this one, step 3's and WEEKLY's), as the whole command, and refuses every other value (a substitution, a variable, a quote, other words) and anything around it (`;`, `&`, `|`, a newline, `#`, a repeated or abbreviated option) [v4.8.0 review; review round 2]. Write down its `period` as `{PERIOD}`, and its `meta_ok` and `alarm`. `alarm` is true only when the week ending at its `until` (the last Sunday 08:30 Prague) is not published and this is that week's Monday run at or after 06:00 Prague: the Saturday sprint and the Tuesday-to-Sunday runs never raise it, so a missed week alarms once.
     3. **The read failed** (no ArtifactData tool, a tool error, no `meta` document, or `meta_ok` false) → run `python3 routines/tools/gsc_weekly.py window --at "{RUN}" --meta-at - --meta-by -` for `{PERIOD}` and `alarm`; the reason is a few plain words (`no tool`, `get failed: {error}`, `no meta document`, `updated unreadable`), written with letters, digits, spaces and `, : ; ' _ -` only: no parentheses, no dots, no link (the guard hook refuses any other reason).
     4. `alarm` true, and `queue/TODO.md` holds no `` `WEEKLY` `` item naming `{PERIOD}` (an earlier run that Monday recorded it) →
        - one `PushNotification`, exactly `GSC WEEKLY · not published · INTAKE {D}: no report for {PERIOD}`, or after a failed read `GSC WEEKLY · not published · INTAKE {D}: weekly check failed ({reason})` (README §5: one line, at most 200 characters, no `#`, no link; shorten the reason to fit, at most 120 characters). {D} is this run's date: the guard hook refuses another date (before the branch is cut, one more than a day from its own UTC date) and any third form. A push the app reports as not sent is not retried;
        - the TODO item `` `WEEKLY` — not published for {PERIOD}: check the WEEKLY routines (repo attached, last runs) — INTAKE {D} `` (after a failed read: `` `WEEKLY` — weekly check failed for {PERIOD} ({reason}): check the WEEKLY routines (repo attached, last runs) — INTAKE {D} ``), → step 6;
        - one line under `## Audit` in the PR body and in the run note: `weekly: not published for {PERIOD} (push sent)`, or `weekly: check failed for {PERIOD} ({reason}; push sent)`. When the Open INTAKE PR bullet ends the run with no PR, the line goes into the session summary and the push is the only record: no later run writes the TODO item (only the Monday run alarms).
     5. `alarm` false → nothing, except a failed read: one run-note line `weekly check failed ({reason})` (session summary when the run ends with no PR). No push.
   - **Open INTAKE PR.** If an open `GSC INTAKE` PR is still open after the sweep:
     - its title ends `[fixing]` → stop with no PR (Jakub is repairing it);
     - it is finished (its title has ` — ` and ends neither `[running]` nor `[fixing]`) and its `updated_at` is more than 20 h old → close it with the supersede PATCH (README §1) and continue (F2): its row and proposal files are still pending on `main`, so this run applies them;
     - otherwise → stop with no PR (it is still running, or gsc-automerge or Jakub will merge it).
   - **Nothing to do** means all of these hold:
     - no pending row file, other than rows that would be held back again (their memo is still missing on `main`, their key's `memos/{KEY}/` does not hold exactly one file, or their key's register row is RETIRED, step 3);
     - no pending proposal;
     - no unrecorded closed-unmerged or reverted ANALYSE PR, meaning none that step 5 would record (its key has a `[ ]` line and its number appears nowhere in `queue/DRAFT_QUEUE.md`);
     - no stalled key still to record, meaning none that step 5 or step 6 would record (README §2);
     - no weekly-watchdog TODO item to record (the Weekly watchdog bullet above).

     Then stop with no PR and end with a session summary.

   Name every PR closed in this step (`[abandoned]`, `[superseded]`) and any held-back rows in the session summary and, when the run goes on, in the PR body; the closing title is each closed PR's record (no comment).
1. **Base.** Record the HEAD sha; the outgoing register's `register_version` N and `register_date`; the TODO version n and date; the DRAFT_QUEUE version n and date. A version is the number after `v` in the file's version line. The next version is the next whole number: v36 → v37, and a dotted v1.1 → v2. Claim the branch and PR (README §2).
2. **Audit** (free-plan compensating control). Re-run the ledger command (README §1) first, so it includes this run's own PR. For the PR body, under `## Audit`:
   - commits on `origin/main` since the previous `GSC INTAKE` PR's `merged_at` (on the first run, the last 7 days) that didn't arrive through a PR merge: `git log --first-parent --since="<merged_at>" --format='%h %s' origin/main`. A subject that ends with `(#<n>)` (squash merge) or starts with `Merge pull request #<n> from ` (merge commit) is a PR merge; anything else is a direct commit. A rebase merge also shows up here as direct commits, so routine PRs are merged with "Squash and merge" or "Create a merge commit", never "Rebase and merge".
   - `claude/gsc-*` branches with no PR in the ledger: `git ls-remote origin 'refs/heads/claude/gsc-*'`. Leave out this run's own branch.
   - changes under `archive/` other than additions (MODEL §7.5: append-only): `git log --first-parent --since="<merged_at>" --no-renames --diff-filter=MD --name-status --format='%h %s' origin/main -- archive/`. List each one. A commit whose subject starts `GSC: RECONCILE` (re-key), `GSC: MODEL` (framework release) or `Revert "` (Jakub's undo of a merged PR) is expected; any other is an archive breach.

   A subject starting `Revert "GSC ANALYSE {KEY} ` or `Revert "GSC REVIEW {KEY} ` (Jakub's undo of a merged PR, MODEL §8.7 item 10) is a PR merge, not a direct commit. Record it: ANALYSE → step 5 marker; REVIEW → a TODO item `` `KEY` — REVIEW reverted {D} (PR #n) `` (n = the reverted PR's number), unless that number already appears in `queue/TODO.md`.

   The lean ledger leaves out old closed PRs: before listing a `claude/gsc-*` branch as having no PR, confirm it with `gh api "repos/jakubhoryna/Value-Investing-Model/pulls?state=all&head=jakubhoryna:{branch}" --jq length` (0 = no PR).

   If any direct commit or archive breach exists, add a TODO item naming it.
3. **Apply the row files, oldest `run_date` then `run_time` first.** First `cp register.csv /tmp/register_outgoing.csv` (the outgoing bytes, for the step-4 snapshot). The register rows are applied here with the tool, which updates `register.csv` only; everything else in step 3 only collects changes (in `/tmp` notes): do not edit `_REGISTER.md`, `queue/TODO.md` or `queue/DRAFT_QUEUE.md` until its archive copy is taken (steps 4–6).
   - **ANALYSE / REVIEW.**
     - Let CUR be the files in `memos/{KEY}/` on `main` (`git ls-tree --name-only HEAD -- memos/{KEY}/`). Never pick a memo by date.
     - If CUR is exactly one file and it is `memo_path`: build the row from it (the `Apply it` bullet below).
     - Else, if `archive/{memo_path}` exists on `main`, the row is **superseded** (a newer REVIEW moved its memo to the archive): apply only its `## Queue update`, consume the file, and log "superseded by {the one file in CUR}".
     - Otherwise **hold back** the row (its memo is not on `main`, or CUR does not hold exactly one file): leave the file in place, list it under `## Held back` in the PR body with the reason, and apply nothing from it. If CUR holds more than one file, also add the TODO item `` `KEY` — memos/{KEY}/ holds {n} files; attended clean-up moves all but the current one to archive/memos/{KEY}/ `` (→ step 6), unless `queue/TODO.md` already has an item `` `KEY` — memos/{KEY}/ holds …``.
     - A row whose key's register row is RETIRED is held back the same way: `apply` refuses it, since a RETIRED row is never re-verdicted (MODEL §7.1 RETIRED) [v4.6.0; G5]. Add the TODO item `` `KEY` — RETIRED row; {JOB} memo {run_date} landed after retirement; attended `retire --undo` or clean-up `` (→ step 6), unless `queue/TODO.md` already has an item `` `KEY` — RETIRED row; …``.
     - Apply it: `python3 routines/tools/gsc_register.py apply --row {file}`. The tool builds the row from the one file in CUR (README §4, memo wins: front matter only), places it in its §7.1 section and order (a REVIEW replaces the key's row, moving section if the verdict changed; an ANALYSE adds a new name) and prints a JSON report. Paste its old → new rows into the PR body. Its `BACKFILL` lines become one step-6 TODO addition per key, `` `KEY` — backfill: {fields} — fill at the next REVIEW ``; its `NORMALISED`, `NOTE` and `LEGACY` lines go into the PR body (`LEGACY`: a memo written before v4.5.0 has no machine fields, so the tool reads its price, trigger, next review, printed multiples and Past level from its text, as the one-time rebuild did).
     - Held name: the tool takes zone, ADD band and sell line from the memo and keeps the held flag and `avg_cost`. It never sets or clears the held flag: a `HELD-MISMATCH` line (memo `position` ≠ register) becomes an open item `ADD: KEY — memo position ≠ register held flag; position event for Jakub` (→ step 6). Never add or remove a portfolio row.
     - A group parent's `## Group dependency` lines → step 6 (Group dependencies, below) [v4.6.0; G4].
   - **INCOMPLETE / PRIOR / QUEUE.** No register change. Their `## Group dependency` (a legacy `INCOMPLETE (dependency: …)` row only) and `Group dependency:` lines, and the re-test markers, go to step 6 (below).
   - **SWEEP.** `python3 routines/tools/gsc_register.py apply --row {file}`. The tool applies each `## Price/ordering refresh` line under MODEL §7.1 and §7.1b: Px, `px_date` and `px_source`, then MCap/FCF and EV/OI and their 3-year and 5-year readings recomputed from the core numbers and the constant holding credit (with the row file's `## FX` rate where the pair matches), and, for a held name, `Last zone check` only when the row file's `## Portfolio table` zone equals the Portfolio `Zone` (MODEL §7.2, J11: a changed held zone keeps the date and the tool says so in a change note; list each such key under `## Held zone changes` in the PR body — the SWEEP's own review request carries it to REVIEW). It skips a key that is out of SWEEP scope (two-or-more-gate AVOID or DNAF, not held; RETIRED, held or not, MODEL §7.1 RETIRED), whose close is not later than the row's `px_date`, whose row comes from a memo dated after the close, or whose `Px unit` differs from the row's `px_unit` (a row with `px_unit` `-` takes the endpoint's currency). Zone, trigger and verdict never change from a sweep. Paste the tool's skip list and the sweep's `## Unit or instrument mismatches` into the PR body.

     → step 6: **merge** this sweep's `## Review requests` into the TODO block `▶ Review requests (SWEEP)`; requests carry forward until reviewed or 4 weeks old (F3):
     - start from the block's current lines;
     - drop a line whose key's current memo date is on or after the line's sweep date (reviewed), or whose sweep date is more than 28 days before D (expired; list the expired keys in the PR body);
     - for each requested key, replace an existing line for that key, or append a new line `` - `KEY` — reason — sweep {run_date} ``; leave out a key whose current memo date is on or after the sweep's run_date;
     - keep the remaining lines in their order.
   - **Every row type**, unless held back (a superseded row: `## Queue update` only):
     - `## Queue update` → step 5.
     - `## TODO additions` → step 6.
     - `## Open items` → step 6: apply to the TODO head block `▶ Open items (register)` under MODEL §7.1: two classes only (pending user decisions, register-integrity holds — pending re-keys and delistings awaiting retirement among them, §7.1 RETIRED), one line each, at most 7 entries. Never remove a pending user decision; you may update its text. A `delisting awaiting retirement` ADD for a key that already has one is skipped; the entry stays until an attended session retires the key (`gsc_register.py retire`) and clears it — INTAKE never retires a key [v4.6.0; G5]. An entry that doesn't fit the classes or the cap goes to the dated TODO block instead, and the PR body says so.
     - `## IDEAS candidates` → step 6: copy verbatim into the TODO head block `▶ IDEAS candidates (attended triage)`, each line prefixed `{run_date} · {KEY} {JOB} —`.
   - **Group dependencies → step 6** (MODEL §2 Group dependencies; §8.7 item 6) [v4.6.0; G4]. A dependency never stops its parent: the parent completes with the part ungradeable, and its ANALYSE or REVIEW row lists each part whose memo is missing or stale under `## Group dependency`. The head block `▶ Group dependencies` holds one line per such part and parent, `` - `HKEY` — dependency of PARENT (run {D}) ``, plus `` - `PARENT` — parent re-run owed (HKEY memo {date}) `` lines for REVIEW priority 1c. INTAKE adds, marks, rewrites and removes lines as below, appending markers after ` — `, and never reorders the block. "Current" means the one memo in `memos/{KEY}/`, dated no more than 15 months before D and written under MODEL v4.5.0 or later, a DNAF memo under v4.6.0 or later (MODEL §2 Group dependencies). For each applied ANALYSE or REVIEW row of KEY, the first three rules run in this order:
     - **Parent landed.** Remove every `` `KEY` — parent re-run owed `` line, and every `dependency of KEY` line whose key the row's `## Group dependency` does not list (the new memo read that part from a current memo, or no longer counts it material).
     - **Add.** Each `## Group dependency` line of the row becomes `` - `HKEY` — dependency of KEY (run {run_date}) ``, unless a line for the same HKEY and KEY is present. Where HKEY's memo is already current on `main` (it landed after the run's base), add `` - `KEY` — parent re-run owed (HKEY memo {memo date}) `` instead, unless that memo is DNAF.
     - **Dependency landed.** A memo of KEY at v4.5.0 or later (a DNAF memo at v4.6.0 or later) removes every `` `KEY` — dependency of … `` line (the subsidiary or holding is now current). Each PARENT whose line it removed gets `` - `PARENT` — parent re-run owed (KEY memo {memo date}) ``, so that the re-run grades the part from that memo, unless a line for the same PARENT and KEY is present, the landed memo is DNAF (still ungradeable), or `memos/{PARENT}/` does not exist (a legacy ANALYSE parent, whose retry reads that memo itself).
     - **Mark.** An INCOMPLETE row of KEY whose key has an unmarked dependency line appends ` — [!] incomplete {run_date}: {gap}` to it, {gap} being the named gap in the row's `pr_title`. A budget gap (`group build exceeds budget`, `method re-test exceeds budget`) in a row of `model_version` v4.8.0 or later is resumed first [v4.8.0; two-run resume]: an unmarked line without a partial marker appends ` — partial {run_date} ({evidence_path})` instead, stays unmarked (a partial marker is not `[!]`) and is taken first (ANALYSE.md step 2; REVIEW.md step 2, priority 1b); a line that already carries ` — partial {D1} (…)` appends ` — [!] incomplete {run_date}: {gap}` and keeps the partial marker, so it records both dates, and the row's own `attended … owed` addition is routed (step 6). A stalled ANALYSE key (README §2, step 5) with an unmarked dependency line appends ` — [!] stalled {D} (PR #a, #b)`, only if `#b` appears nowhere in `queue/TODO.md`. A marked subsidiary or holding is ungradeable: the parent counts it WEAK with its weight in the group grades, with no credit (`sub dependency`), and completes (ANALYSE.md step 5). A mark re-queues no parent: the parent already read the part as ungradeable.
     - **Rewrite.** A row's `## Queue update` line `Group dependency: KEY → prior KEY2` rewrites that line's key to `KEY2` and appends ` (prior of KEY)`, or removes the line when KEY2's memo is current. `Group dependency: KEY → memo exists` removes the line when KEY's memo is current and otherwise leaves it for REVIEW priority 1c. A line removed here lists its parent as Dependency landed does, with that memo's date. `Group dependency: KEY → retired` and `Group dependency: KEY → no listed security` remove the line; each PARENT whose line it removed gets `` - `PARENT` — parent re-run owed (KEY retired {run_date}) `` or `` - `PARENT` — parent re-run owed (KEY no listed security {run_date}) `` for REVIEW priority 1c, unless a line for the same PARENT and KEY is present or `memos/{PARENT}/` does not exist: a line that has ceased to trade is no longer a listed dependency, and the parent re-reads that part from its own filings (MODEL §2 Group dependencies, §8.7 item 6; §7.1 RETIRED; ANALYSE.md steps 2 and 5) [v4.6.0; G5].
     - **Legacy rows.** A pending `INCOMPLETE (dependency: …)` row from a run before v4.6.0 is applied once, as before, for its dependencies: each `## Group dependency` line is added (Add, with the row's key as PARENT). Its parent is not held back, because a dependency no longer stops one: an ANALYSE parent's queue line takes no `[!] incomplete` marker and stays `[ ]` with ` — retry (dependency no longer blocks, {D})` appended (step 5), and a REVIEW parent's re-test or `parent re-run owed` line takes no marker (Re-test markers, below). A `[!] incomplete {D0} — {path}` queue line whose key still has `dependency of` lines (set for a dependency gap before v4.6.0) resets to `[ ]` with the same note, unless it already carries that note.
     - *Worked example (illustrative).* A REVIEW of `INVE-B.ST` completes with `AZN.L` and `SEB-A.ST` ungradeable (no current memos: `sub dependency`, `credit owed`), its row listing both under `## Group dependency` → two lines `` `AZN.L` — dependency of INVE-B.ST (run 2026-10-20) `` and `` `SEB-A.ST` — … ``. ANALYSE takes `AZN.L` next; its memo lands → that line goes and `` `INVE-B.ST` — parent re-run owed (AZN.L memo 2026-10-21) `` is added. `SEB-A.ST`'s ANALYSE ends INCOMPLETE → its line ends ` — [!] incomplete 2026-10-22: data access`, and no parent is re-queued. REVIEW takes `INVE-B.ST` at 1c, grades `AZN.L` from its memo and still counts `SEB-A.ST` WEAK with its weight, with no credit. When that memo lands, its row lists `SEB-A.ST` again: the `SEB-A.ST` line stays, with its marker, and the `parent re-run owed` line goes.
   - **Re-test markers → step 6** (MODEL §8.7 item 6; critic B1). For an INCOMPLETE REVIEW row of KEY, the key's "re-test lines" are its `▶ Method re-tests v4.8.0`, `▶ Method re-tests v4.6.0` and `▶ Method re-tests v4.5.0` lines and its `parent re-run owed` lines; each is marked by appending after ` — `, never reordered.
     - **Budget gaps — two-run resume [v4.8.0].** For `group build exceeds budget` and `method re-test exceeds budget` in a row of `model_version` v4.8.0 or later:
       - each re-test line without a partial marker gets ` — partial {run_date} ({evidence_path})`, the row's `evidence_path` (REVIEW takes the key first at its next run on a later date, REVIEW.md step 2);
       - a re-test line that already carries ` — partial {D1} (…)` has that marker replaced by ` — attended re-test owed (partial {D1}, {run_date})` (for a group build gap ` — attended group build owed (partial {D1}, {run_date})`); the row's own `attended … owed` TODO addition is routed as any other (REVIEW skips the key until Jakub clears both);
       - a key with neither a re-test line nor a `dependency of` line (Mark, above): if `queue/TODO.md` has no `` `KEY` — partial … `` item, route `` `KEY` — partial {run_date} ({evidence_path}) `` to this INTAKE's dated block (step 6), which REVIEW reads at priority 1b; if it has one, remove that item: the row's routed `attended … owed` addition replaces it and names both records.
       - a row below v4.8.0 (a run that started before the release) is applied as before: its `attended … owed` addition is routed, and its re-test lines take no marker.
     - A legacy `dependency: …` gap: nothing (Legacy rows, above).
     - **Any other gap:** each re-test line, and the key's routed `` `KEY` — partial … `` item (a key with no queue line, Budget gaps above) [v4.8.0], without an `incomplete` marker gets ` — incomplete {run_date}: {gap}` (REVIEW skips the key for 14 days); a line or item that already carries one ends instead ` — attended re-test owed (incomplete {first date}, {run_date})` (REVIEW skips the key until Jakub clears the marker). A partial marker on the line or item stays: the resume is still owed when the 14 days have run, and the routed item is never retried at the top of priority 1b on every run.
   - **REVIEW applied** → step 6: remove its key from `▶ Review requests (SWEEP)` when the REVIEW's run_date is on or after that line's sweep date. When the REVIEW wrote a memo (not INCOMPLETE), also remove every `` `KEY` — partial … `` item of its key, wherever it sits in `queue/TODO.md` (the resume landed) [v4.8.0]. When the REVIEW wrote a memo (not INCOMPLETE) whose `model_version` is v4.5.0 or later, also remove its key's line from `▶ Method re-tests v4.5.0` and from every `▶ Backfill owed — …` block (`register rebuild …` and `retrigger …`): that memo applied the codified rules, carries every v4.5.0 field and states its trigger at the no-cash bound (`trigger_basis: no-cash`; lint-memo). A memo written under an earlier version (a run that started before the release) leaves those lines in place.
   - **v4.6.0 re-test landed** → step 6: an ANALYSE or REVIEW memo (not INCOMPLETE) whose `model_version` is v4.6.0 or later removes its key's line from `▶ Method re-tests v4.6.0`: it applied the v4.6.0 Gate-0, lens and group rules and the G6 pairing. A memo written under an earlier version leaves the line in place.
   - **v4.8.0 re-test landed [v4.8.0]** → step 6: an ANALYSE or REVIEW memo (not INCOMPLETE) whose `model_version` is v4.8.0 or later removes its key's line from `▶ Method re-tests v4.8.0`. It applied the v4.8.0 method rules (MODEL §8.2 step 3), and, being written under v4.8.0, every older one too: it also removes the key's lines from the v4.6.0 and v4.5.0 blocks, under the two rules above. A memo written under an earlier version leaves the line in place.
4. **Regenerate the register (§7.4a generation rule)** — only if step 3 changed at least one register row (a tool report with changes; `register.csv` then differs from `main`). A change to the open items alone makes no register version (they live in TODO). Otherwise write no snapshot and no new version; queue and TODO changes still go ahead.
   - **Snapshot first.** `mkdir -p archive/registers/{YYYY}`, then `cp _REGISTER.md archive/registers/{YYYY}/REGISTER_v{N}_{register_date}.md` and `cp /tmp/register_outgoing.csv archive/registers/{YYYY}/REGISTER_v{N}_{register_date}.csv`, where YYYY is the year of the outgoing `register_date`. They are byte copies of the outgoing files: never write them with the Write tool. If either path already exists on `main`, something else wrote the register: treat it as an unfixable breach (step 7).

The tool writes the complete `_REGISTER.md` — front matter (version, date, `names_total`, `verdict_split` and `portfolio_names` derived from the rows), legend, PORTFOLIO, BUY, WATCH, AVOID one gate, AVOID two+, DNAF, RETIRED (the master tables with the two averaged columns, `MCap/FCF 3y · 5y` and `EV/OI 3y · 5y`), sorted by EV/OI — and refuses a cell over 160 characters, an AVOID row with no failed gate, a duplicate key or an unknown section.

5. **Update `queue/DRAFT_QUEUE.md`** — only if something changes. First `cp queue/DRAFT_QUEUE.md archive/queue/DRAFT_QUEUE_v{n}_{date}.md` (the outgoing version and its date). It never overwrites another marker, so a later prior marker can't replace `[x] {D}`. List any skipped update in the PR body.

On a line that already carries the note (the resume overran too), the marker is `[!] incomplete {D} — {evidence_path}` as for any INCOMPLETE row, the note stays, so the line records both dates, and the row's `attended group build owed` addition is routed to TODO (step 6).

   - `[ ] … — retry (dependency no longer blocks, {D})` — step 3's Legacy rows rule appends the note to a group parent's `[ ]` line, or resets its `[!] incomplete {D0} — {path}` line to `[ ]` and appends it (MODEL §2 Group dependencies) [v4.6.0; G4]. It is the only marker INTAKE ever takes back to `[ ]`. Like it, a partial note is a trailing note: a later marker replaces only the leading token and keeps the note.
