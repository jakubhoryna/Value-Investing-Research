## How to maintain this file (the "one added line per analysis" rule)

1. **New ANALYSE** → append one row, alphabetically by ticker. Update `names_total`, the verdict split in the front matter, and the verdict-summary table.
2. **REVIEW** → replace the existing row in place, bump that name's `Ver`, and add a change-log line below. Do **not** keep both versions.
3. **File version** → bump `register_version` (v2 → v3 …) and `register_date` whenever rows are added or replaced, and log it. This is what makes the register itself versionable rather than only the memos.
4. **Source of truth precedence** → register vs. memo disagreement: trust the memo. Memory vs. register: trust the register.

To keep this as the project's canonical `_REGISTER.md`, save the table (and header) over the existing file; the schema is identical, so it drops in cleanly.
